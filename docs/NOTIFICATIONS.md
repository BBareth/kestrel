# Notifications (Web Push)

Standard Web Push with VAPID (RFC 8030/8291/8292), encrypted `aes128gcm` payloads. Works on iOS/iPadOS
16.4+ **only for the Home Screen app** (not in a Safari tab), and on desktop Chrome/Edge/Firefox/Safari.

## Enable

1. iPhone: install the PWA first ([PWA.md](PWA.md)) and open it from the Home Screen.
2. **Notifications → Enable notifications** → allow the system prompt.
3. **Send test notification** — it should arrive within seconds. A successful delivery also ticks the
   "Notifications tested" readiness item.

**Disable:** *Disable notifications* on the same page (or remove the device under *Registered devices*).
Per-category switches decide what you receive; **critical** alerts (emergencies, halts, kill switch,
unknown positions) are always delivered.

| Category | Example |
|---|---|
| Trade opened | "BTC LONG opened at $84,750 · stop $84,400 · PAPER" |
| Stop-loss hit | "BTC LONG stopped at $84,400 · −42.10 USDT" |
| Take-profit hit | "BTC LONG TP1 hit at $85,030" |
| Trade closed | manual / emergency / external / liquidation |
| Setup detected | "BTC potential LONG setup detected · confidence 78 · R:R 2.3" |
| Risk | "Daily loss limit reached — trading disabled until tomorrow (UTC)", halts, emergencies |
| System | "Binance connection lost", "Market data stale", "Protective order restored" |
| Live mode | "Live trading enabled" / "disabled" |
| AI (off by default) | "AI suggests closing BTC LONG" (advice only) |

Identical notifications within 5 minutes are suppressed; every notification (sent or suppressed) is
listed in the history with its delivery result. Subscriptions the push service reports as gone (404/410)
are removed automatically.

## Server configuration

`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` (generated by `scripts/gen-vapid.sh`; raw P-256 keys,
base64url) and `VAPID_SUBJECT` (`mailto:` or `https:` contact; currently `https://barex.ch`).
**Do not regenerate the keys** once devices are subscribed — every subscription would stop working.

Verified by `tests/test_webpush_crypto.py`: the VAPID JWT is ES256-signed with the right audience and
the payload decrypts exactly as a browser does.

## iOS specifics / troubleshooting

* "Enable" disabled or an iPhone hint shown → you are in Safari, not the Home Screen app.
* Nothing arrives → check Focus modes; Settings → Notifications → Kestrel; the device list shows the
  last successful delivery and failures.
* iOS silently drops the permission if a push does not show a notification — the service worker always
  shows one, even for malformed payloads.
* The phone does not need to reach the server to receive pushes (Apple delivers them), only to open the app.
